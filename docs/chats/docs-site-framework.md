# Documentation site: framework and hosting

**Questions asked:** how do we turn `docs/` into a proper site, and where does it live?

**Decisions:**

1. Build it with **Astro + Starlight**, in a self-contained **`site/`** project.
2. Output **static HTML** — stay **host-agnostic** (no Netlify/Vercel/Cloudflare-specific config).
3. Keep the existing Vite showcase at the root untouched; the site is an additional consumer of
   `@sakhalabs/ui`.

---

## Why Astro + Starlight

| Criterion | Why it fits |
|---|---|
| **Live React demos** | `@astrojs/react` islands let the real `@sakhalabs/ui` components run inside the docs — no screenshots, no drift. |
| **Docs out of the box** | Sidebar, full-text search (Pagefind), dark mode, autogenerated TOC, sitemap — no plugins to wire up. |
| **Content reuse** | The existing Markdown in `docs/` ports over with frontmatter and nothing else. |
| **Static output** | `astro build` emits plain HTML/CSS/JS → deploy anywhere, works on slow networks. |
| **Zero JS by default** | Only the demo islands hydrate; the rest of the page is static HTML. |

## Alternatives considered

| Option | Why not |
|---|---|
| **Docusaurus** | Heavier (React SPA-ish), more config, React-version coupling with the demos. |
| **VitePress** | Excellent, but Vue islands — our demos are React. |
| **Nextra / Next.js** | Runtime + build heavier than needed for static docs; React version constraints. |
| **Plain Vite + Markdown** | We'd rebuild search, sidebar, dark mode and routing ourselves. |

## Hosting

Deliberately undecided — the build is plain static files (`site/dist/`), so any of Netlify,
Cloudflare Pages, GitHub Pages, S3 + CDN, or a plain web server works. Only `site/astro.config.mjs`
→ `site:` needs the real URL (canonical links + sitemap) once a host is chosen.

## Layout

```
site/                    ← self-contained Astro project (its own package.json + node_modules)
├── astro.config.mjs     ← Starlight config: title, sidebar, social, custom CSS
├── src/content/docs/    ← the pages: landing (splash), getting-started, theming, tailwind,
│                          components, catalog/*, publishing, changelog
├── src/components/demos.tsx  ← live React demos (also on the Theming page)
└── src/styles/custom.css     ← imports @sakhalabs/ui/styles.css + demo framing
```

The library is consumed as `file:../packages/ui`, so the demos always run the **actual package**
rather than a copy.

> **Cascade note:** the library stylesheet lives in `@layer components`, so it never fights
> Starlight's (unlayered) chrome — the same layer story documented in `docs/tailwind.md`.

---

*Status: decided — Astro Starlight in `site/`, static and host-agnostic. Recorded 2026-10-20.*
